# Результаты проверки

Оценка RAG: 2 ноября 2026. Проверка интерфейса: 3 ноября 2026.

Проверена базовая конфигурация: E5 + BM25 + RRF, gate 0.8 / 0.5, без reranker,
генерация через локальный LM Studio. MacBook Air M1 (2020), 8 ГБ RAM.

LLM: Ministral 3 3B Instruct Q4_K_M, контекст 8192, temperature 0, max_tokens 2048,
один запрос за раз. Текстовый GGUF занимает 2 146 498 240 байт; LM Studio дополнительно
использует файлы своей модели. SHA-256 и параметры записаны в [runtime.json](evaluation/runtime.json).
E5 закреплена на ревизии `d128750597153bb5987e10b1c3493a34e5a4502a`, устройство CPU.

## Объём проверки

- 87 офлайн-тестов прошли: PDF, очистка, чанкинг, SQLite/Chroma, retrieval, API, SSE,
  история, ошибки провайдеров, метрики и проверка происхождения оценок.
- Выполнены два итоговых прогона: 28 ответов dev и 28 test. Ошибок провайдера,
  пустых ответов и прерванных генераций в них нет.
- Все 56 ответов автоматически оценены моделью gpt-6.1-sol по опубликованной рубрике.
  В review-файлах указан тип проверяющего `assistant`; человеческой экспертизы не было.
- HTTP-сценарий с LM Studio: загрузка PDF, индексация, дубликат,
  валидация, скачивание, SSE и сохранение истории.
- В браузере проверены загрузка PDF, вопрос, источники и HTML-схема. Схема имеет
  33 выбираемых узла; проверены пояснения, отсутствие ошибок JavaScript и горизонтального
  переполнения при ширине 390 пикселей.
- Ruff, синтаксис JavaScript, `uv.lock` и Docker Compose config проверены.

## Поиск до gate

Оба набора содержат по 16 ответимых и 8 неответимых одиночных вопросов.
Метрики поиска относятся только к ответимым. Каждый документ даёт восемь чанков;
поэтому выбор top-6 здесь значительно проще поиска в большой коллекции.

| Метод | Dev: Complete@6 | Test: Complete@6 | Test: средний evidence recall@6 | Test: MRR@6 |
|---|---:|---:|---:|---:|
| BM25 | 15/16 | 15/16 | 0.9375 | 0.9375 |
| Dense E5 | 16/16 | 15/16 | 0.96875 | 0.96875 |
| Hybrid RRF | 16/16 | 16/16 | 1.0 | 0.96875 |

Все размеченные доказательства сохранились после извлечения и чанкинга.
При таком размере набора разница между 15/16 и 16/16 недостаточна для вывода
о преимуществе hybrid. Даже с полным контекстом модель ошибалась; случаи приведены ниже.

## Gate

На dev исходные 0.72 / 0.5 дали 0/16 ложных отказов и 7/8 ложных пропусков.
Заранее описанная сетка выбрала 0.8 / 0.5 по минимуму balanced error.

| Набор | Ложные отказы на ответимые | Пропущены вопросы без ответа |
|---|---:|---:|
| Dev, исходные пороги | 0/16 | 7/8 |
| Dev, выбранные пороги | 1/16 | 4/8 |
| Test, те же выбранные пороги | 1/16 | 5/8 |

После просмотра test пороги не менялись. Gate остаётся грубым фильтром тематической
близости. Из 56 итоговых ответов девять отказов сформировал gate, остальные
47 ответов сформировала LLM. Вызовы уточнения вопроса в этот счётчик не входят.

## Ответы: разбор по рубрике

В ячейках указано число положительных оценок и число применимых случаев.
Каждое поле оценивается отдельно: верные факты могут быть неполными, а правильный расчёт
может сопровождаться неверной ссылкой. Отсутствие ответа из-за gate входит в оценку
конечного результата.

| Набор и тип | Факты | Полнота | Поддержка контекстом | Уместность отказа | Поддержка цитатами |
|---|---:|---:|---:|---:|---:|
| Dev: ответимые одиночные | 12/16 | 14/16 | 12/16 | 14/16 | 12/14 |
| Dev: неответимые одиночные | 8/8 | 8/8 | 8/8 | 8/8 | 1/1 |
| Dev: ходы диалогов | 4/4 | 4/4 | 4/4 | 4/4 | 3/4 |
| Test: ответимые одиночные | 13/16 | 14/16 | 13/16 | 15/16 | 11/15 |
| Test: неответимые одиночные | 8/8 | 8/8 | 8/8 | 8/8 | 0/1 |
| Test: ходы диалогов | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 |

Чистый отказ без содержательных утверждений не требует цитаты и исключён только
из её знаменателя. Объясняющий отказ с фактом о документе требует подтверждающей ссылки.
Физический номер страницы в круглых скобках может подтверждать утверждение при разборе,
но не распознаваться кликабельным шаблоном интерфейса. Соблюдение языка ответа и
формата XML/цитат отмечено в пояснениях, отдельный балл за него не рассчитывался.

выдуманные названия и другие смысловые ошибки.

### Время

Медиана полного ответа среди случаев с генерацией: 5.9 с на dev и 6.0 с на test.
Медиана времени первого текста: 4.3 и 3.7 с. Диалоги включают дополнительное уточнение.

на указанной машине. Нагрузочный тест не проводился; пиковая RAM и swap не измерялись.

повторная загрузка доступна в библиотеке. Через FastAPI и LM Studio проверены
загрузка примера, первый вопрос о сроке службы, ответ «10 лет», цитата страницы 9

после 503 дополнительно проверены на отдельном UI-стенде с фиксированными ответами API.

## HTTP и интерфейс

Демонстрационный PDF: 9 страниц, 15 чанков. Ответ модели на вопрос о гарантии:
36 месяцев со дня продажи, ссылка на стр. 9. Поток содержал `sources`, `token`, `done`;
сообщения сохранены в SQLite. Повторный файл получил код 200, новый файл получил 202. Для не-PDF вернулся код 415,
для пробельного вопроса вернулся 422. Исходный PDF скачан с кодом 200.
После перезапуска документ остался ready, сохранились четыре сообщения и снова
прошёл поиск с SSE. Через браузер получен ответ о сроке службы 10 лет и раскрыт
источник на стр. 9. Очистка истории и удаление дали 204; после удаления документ
получил 404, список документов пуст. Данные сценария:
[http-check.json](evaluation/http-check.json).

## Ограничения проверки

Независимая человеческая экспертиза не выполнялась. Корпус мал, синтетический,
с одной схемой PDF-вёрстки и одним итоговым прогоном на набор. В одном dev-примере
обнаружена неоднозначность эталона. Доверительные интервалы и межэкспертное согласие
не оценивались.

Reranker, Ollama и Anthropic в этом прогоне не подключались к моделям и внешним API.
Docker Compose config валиден, но образ не собирался и контейнер не запускался:
Docker daemon недоступен. Нагрузочная устойчивость, OCR, сложные таблицы,
несколько процессов и произвольные prompt injection этой проверкой не подтверждаются.
